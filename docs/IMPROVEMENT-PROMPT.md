> **実装状況（2026-06-14 時点）**
> 専門家レビューを待たず、要望順に実装中。
> - ✅ パーツ別の縫い方（サテン/タタミ/自動）— 永続化（`Region.fillType`）
> - ✅ **パーツ別のステッチ方向（角度）**（`Region.angleDeg`）— ステッチタブのスライダー/
>   クイックボタン＋キャンバスの青いつまみをドラッグして向きを引ける（§8 フェーズ3 相当）
> - ✅ **オブジェクトモデルの土台（フェーズ1）**: `EmbroideryObject`（`src/core/object.ts`）を導入。
>   不変の `id`（選択・縫い順の同一性）と `baked`（マニュアル編集済み針列の温存）を持つ。
>   digitize は安定 id を `run.objectId` に使い、`baked` があるオブジェクトは再生成しない。
>   UI に「このパーツの針を固定（マニュアル化）」を追加（個々の針編集 = フェーズ7 の入口）。
> - ✅ **差分再生成（フェーズ2）**: オブジェクトごとに本体ランをキャッシュ（形状参照＋
>   生成パラメータ＋前後文脈で判定）。変更のないパーツは縫い直さず再利用する。
>   方向ドラッグ中は診断/シーケンスの再構築も省いてキャンバスだけ軽量更新する。
>   出力はキャッシュ無しと完全一致（結果を変えない）。
> - ✅ **ターニングステッチ＝流れる向き（フェーズ4）**: `Region.angleLines`（方向線）を導入。
>   2本以上で角度フィールドを空間補間し、その等位線（marching squares）を縫い目の行にして
>   葉・花弁のように向きが流れるタタミを生成（`src/stitch/turning.ts`）。穴あき/退化時は
>   通常タタミにフォールバック。UIは「方向線を引く」モードでキャンバスにドラッグして作図。
> - ✅ **輪郭ノード編集の統合（フェーズ5）**: 既存のノード編集をオブジェクトモデルに統合。
>   パネルの「輪郭を編集」で選択パーツに絞って編集開始、ノードをドラッグすると
>   そのパーツだけライブで縫い直す（差分再生成・オブジェクトidは維持）。smooth ノードは
>   Catmull-Rom 曲線。破棄で開始時の形状に正しく復元。
> - ✅ 回帰修正: `compensateRegion` がパーツ固有プロパティを失っていたバグを修正
> - ⚠ 既知の制限: `baked`/`angleLines` はまだプロジェクト(.json)に保存されない（次段で対応）。
>   ターニングは穴なし・凸寄りの面が対象（凹面では渡りが出ることがある）。
> - ⏳ 次: 個々の針の編集UI（フェーズ7）／保存対応（baked/angleLines を .json へ）／

## §1. このプロンプトのゴール（一言で）

現状の PP1 Stitch Studio v2 は「画像/SVG/文字を**自動で**刺繍化して、安全に縫えるデータを出す」
ツールです。しかし利用者が本当に欲しいのは、**BERNINA V9 / Wilcom Hatch 3 / Embroidery Legacy の
ように、生成された刺繍を“手で細かく直せる”編集ソフト**です。具体的には次の3つができること：

- **(A) ステッチの方向を指定・修正できる**（面ごとに角度を変える／曲面に沿って向きを流す）
- **(B) ステッチの種類をパーツ単位で選べる・調整できる**（サテン／タタミ／走り縫い／モチーフ等、密度や下縫いも）
- **(C) デザインそのものを修正できる**（輪郭ノードの編集、オブジェクトの追加・削除・並べ替え、
  個々の針（ステッチ点）の編集、再生成を伴うサイズ変更）

この3つを「自動化の便利さは残したまま」実現することが目標です。

## §2. いま到達できていること（現状の正確な把握）

> 実装済みのコードを読んだ上での事実ベースの整理。改良の出発点。

- **中間表現（データモデル）**
  - `StitchPlan { name, blocks: ColorBlock[] }`
  - `ColorBlock { thread, runs: StitchRun[] }`
  - `StitchRun { stitches: Point[], connection: 'continuous'|'jump'|'trim', objectId?, stitchType? }`
  - 座標は 0.1mm 整数・デザイン中心原点。**糸切りは Run と Run の“間”の属性としてのみ存在**し、
    面の途中で糸を切れない設計（前作の「少し縫って糸切り」問題を構造的に根絶した核心。**維持必須**）。
- **入力 → 領域（Region）**
  - `Region { outer, holes, color, fillType? }`（`fillType?` は今回パーツ別の縫い方用に追加済み）
  - 画像は Lab k-means 減色 → 境界追跡 → 簡略化・平滑化、SVG はパス取り込み。
- **ステッチ生成**
  - `src/stitch/digitize.ts` の `digitizeRegions()` が `Region[]` 全体から `StitchPlan` を生成。
  - フィル種別：`tatami` / `satin` / `auto`（細い面は自動でサテン）。下縫い（edge/tatami 等）、
    Pull/Push 補正、Auto Density、Closest Join（縫い順最適化）、Travel on Edge、Branching あり。
  - **ステッチ角度はデザイン全体で1つ（`settings.angleDeg`）**。面ごとの個別角度は未対応。
- **編集系**
  - ベクター編集（`src/ui/vectorEdit.ts`・`src/vector/`）：ノード corner/smooth、追加/削除、Snap。
    ただし**領域→編集形状→領域に変換して“全再生成”**する方式。
  - 今回追加：パーツをクリックして縫い方（サテン/タタミ/自動）を指定。
- **計画・確認**：縫い順最適化、糸切り判定、シーケンスビュー、ステッチシミュレーター、診断、自動針数削減。
- **出力**：PES（Brother 64色）/ DST。100mm 枠・12,000 針上限。ブラウザ完結。

## §3. なぜ「欲しいソフト」と違うのか（根本原因）

プロ向けソフトとの決定的な差は、機能の数ではなく**設計思想**にあります。

- **現状：手続き的・使い捨てモデル**
  `Region[]` を入力に、編集のたびに `recomputeStitches()` が**プラン全体をゼロから作り直す**。
  そのため「この面だけ角度を変えた」「この針を1つ動かした」といった**手作業の編集結果を保持できない**。
  次の再生成で消える。これが“細かい修正ができない”の正体。

- **プロ向け：オブジェクト指向・永続モデル**
  デザインは**オブジェクト（縫いパーツ）の集まり**で、各オブジェクトが
  「輪郭・ステッチ種別・方向（角度線）・密度・下縫い・リードイン/アウト・効果」を**自分の属性として保持**。
  再生成はオブジェクト単位で行い、**手で入れた針（マニュアルステッチ）はそのまま温存**される。
  選択 → プロパティ変更 → そのオブジェクトだけ縫い直し、という編集ループが回る。

**したがって本改良の中心は「描画機能の追加」ではなく、データモデルを
“使い捨ての Region[]” から “永続的な EmbroideryObject[]” へ移行すること**です。
ここを設計し直さないと、UI をいくら足しても「直せない」問題は解決しません。

## §4. 目指す編集体験（参照ソフトの“思想”を、独自実装で）

> 各項目は「参照ソフトでの一般的な呼称（思想理解のため）」→「PP1 で実現したいこと」の順。
> 呼称はあくまで思想共有用。PP1 の UI・名称は独自にする。

### 4-1. オブジェクトモデルと選択・プロパティ
- 参照思想：すべては「オブジェクト（セグメント）」。選択すると右パネルに全プロパティが出る。
- PP1：`EmbroideryObject` を新設。種別・輪郭・色・縫いパラメータ・効果・縫い順位置を保持。
  キャンバスで選択 → プロパティパネルで編集 → そのオブジェクトのみ再生成。

### 4-2. ステッチ種類（パーツ単位で選択・調整）
- サテン（幅可変・コラムサテン：2本の輪郭＋渡し）、タタミ/ステップ（パターン・行オフセット）、
  走り縫い（シングル/トリプル/モチーフラン）、複雑フィル（穴・凹み対応の単一連続フィル）、
  輪郭フィル/スパイラル、エコー/リップル、クロスステッチ、マニュアル（点打ち）など。
- PP1：まず「サテン（幅可変）・タタミ（パターン/角度）・走り縫い（単/三重/モチーフ）・マニュアル」を軸に。

### 4-3. ステッチ方向の制御 ★最重要・ユーザー要望の核心
- 参照思想：オブジェクトに**1本以上の“方向線（angle line）”**を引いて向きを決める。
  複数本引くと、その間を**補間して向きが滑らかに流れる（ターニングステッチ）**。
  サテンでは輪郭に直交、フィルでは指定角度。
- PP1：オブジェクトに方向線を**0..N本**持たせる。0本＝既定角度、1本＝一定角度、
  2本以上＝区間補間で“流れる”タタミ/サテン。キャンバス上でドラッグして引く。

### 4-4. 輪郭（ノード）編集 — 再生成を伴う
- 参照思想：Reshape ツール。コーナー/カーブ（ベジェ）ノードの追加・削除・種別変更、ハンドル操作。
- PP1：既存のノード編集を**オブジェクトに統合**し、編集→**そのオブジェクトのみライブ再生成**。
  真のベジェ曲線対応を検討（現状は corner/smooth + Chaikin 平滑）。

### 4-5. 個々のステッチ（針）編集
- 参照思想：Stitch Edit モード。針点を選択して移動／挿入／削除、範囲選択。
- PP1：オブジェクトを「マニュアル化（ベイク）」すると、その針列を直接編集可能にする。
  ベイク後は再生成対象から外し、手編集を温存（§3 の永続モデルが前提）。

### 4-6. 下縫い・接続・タイ/トリム（オブジェクト単位）
- 下縫い種別をオブジェクトごとに。リードイン/アウト、タイイン/オフ、糸切り/ジャンプの方針。
- PP1：**糸切り根絶の核心ルールは維持**しつつ、オブジェクト境界での接続方針を選べるように。

### 4-7. 縫い順（シーケンス）編集
- 参照思想：オブジェクトをツリーで並べ替え、色順最適化、前後移動。
- PP1：シーケンスビューを**ドラッグで並べ替え可能**にし、選択と双方向連動。

### 4-8. 効果
- Pull/Push 補正、密度・グラデーション密度、ブラックワーク/アウトライン化、
  アップリケ工程、3D パフィー/トラプント、カービング（スタンプで密度を彫る）。
- PP1：既存の Pull/Push・パフィー・アップリケを**オブジェクト属性化**し、密度グラデーションを追加。

### 4-9. 再生成を伴うサイズ変更・変形
- 参照思想：拡大縮小で**ステッチを再計算**（密度を保つ）。単純スケールではない。回転/スキュー/ミラー。
- PP1：オブジェクトの拡大縮小で密度維持の再生成。デザイン全体の回転/ミラーも。

### 4-10. 手動デジタイズ（新規オブジェクトを“描いて”作る）
- 参照思想：クリック/ドラッグで輪郭を入力し、種別を選んでオブジェクト化。
- PP1：ペン入力でサテン列・フィル・走り縫いを新規作成できるツール。

### 4-11. 自動デジタイズは残す
- 画像/写真/SVG/文字の自動変換は維持しつつ、出力を**編集可能なオブジェクト**として吐く
  （現状は最終 Plan のみで、後から細かく直せない）。

## §5. 守るべき制約（PP1 / Artspira の現実）

- 刺繍枠 **100mm×100mm**、**12,000 針上限**（超過は警告＋自動削減）。
- 出力 **PES（Brother 64色保持）/ DST**。ブラウザ内完結・サーバー送信なし。
- **糸切り根絶設計の核心（Run 途中で切れない／面は1本の連続 Run）を絶対に壊さない**。
- 商用ソフトの **UI・名称・アイコン・内部仕様を複製しない**（思想の参考のみ）。
- 既存の自動化フロー（かんたんモード）を壊さず、編集機能は「プロモード」側に積む。

## §6. 想定する新データモデル（たたき台。レビューで詰める）

```ts
// 永続オブジェクト：これが“真実”。Plan はここから生成される派生物。
interface EmbroideryObject {
  id: string;
  kind: 'satin' | 'fill' | 'run' | 'manual' | 'lettering';
  outline: VectorPath;            // ベジェ対応の輪郭（穴も保持）
  holes: VectorPath[];
  color: ThreadColor;
  // 方向制御
  angleLines: DirectionLine[];    // 0..N。空=既定角、2本以上=補間で流れる
  // 縫いパラメータ（kind 依存）
  params: SatinParams | FillParams | RunParams | ManualParams;
  underlay: UnderlaySpec[];
  effects: { pullComp; pushComp; densityGradient?; ... };
  lead: { in?: LeadSpec; out?: LeadSpec; tie; trimPolicy };
  order: number;                  // 縫い順
  baked?: StitchRun[];            // マニュアル化後の手編集針列（あれば再生成しない）
  dirty: boolean;                 // 再生成が必要か（差分再計算用）
}
```

- **差分再生成**：`dirty` なオブジェクトだけ縫い直し、他は前回結果を再利用 → 編集が軽快に。
- `baked` があるオブジェクトは個々の針編集を保持。
- 既存の `Region` ベース生成は `kind:'fill'/'satin'` への移行ラッパーにできる（後方互換）。

## §8. Claude への実装フェーズ分割（確定後に使う）

> 「最小で価値が出る順」かつ「いつでも縫えるデータが壊れない順」。

1. **モデル移行の土台**：`EmbroideryObject` 導入＋差分再生成。既存自動フローを object 化（見た目は不変、内部刷新）。
2. **オブジェクト選択＆プロパティパネル**：種別・色・密度・下縫いをパーツ単位で編集（再生成連動）。
3. **ステッチ方向①**：1本の方向線で面ごとの一定角度。キャンバスでドラッグ入力。
4. **ステッチ方向②（ターニング）**：複数方向線の補間で“流れる”サテン/タタミ。
5. **輪郭ノード編集の統合**：ベジェ＋ライブ再生成（オブジェクト単位）。
6. **縫い順ドラッグ編集**＋選択連動。
7. **個々のステッチ編集（マニュアル化/ベイク）**：針の移動・挿入・削除、温存。
8. **手動デジタイズ（ペン入力で新規オブジェクト）**。
9. **効果拡張**（密度グラデーション・カービング等）／**再生成サイズ変更**。

各フェーズは「ビルド通過＋全テスト緑＋実機で縫える PES が出る」を完了条件にする。

## §9. 有識者への質問（ここに答えて v0.2 にする）

1. **優先度**：A(方向) / B(種類) / C(デザイン修正) のうち、家庭機 PP1 でまず欲しいのはどれ？
   §8 の順番はこれで良いか、入れ替えるべきか。
2. **ステッチ種類**：家庭刺繍で“絶対に要る”種類は？（例：可変幅サテン、流れるタタミ、三重走り、
   モチーフラン、クロスステッチ…）。逆に「無くて良い」ものは？
3. **方向制御**：方向線は「面ごとに1本の角度」で実用上足りるか、最初から
   「複数線の補間（流れる向き）」まで要るか。曲面（葉・花弁等）の表現にどこまで必要か。
4. **針単位編集**：実際の修正で「個々の針を動かす」需要はどれくらい？ それとも
   「輪郭と角度を直せば十分」か（＝§4-5 の優先度）。
5. **品質基準**：サテンの最大幅、タタミの推奨密度、下縫いの標準、Pull/Push の目安など、
   PP1 と一般的な家庭用生地での“良い既定値”を具体的な数値で。
6. **入力素材**：実際に直したいのは「自動生成の結果の手直し」が中心か、
   「ゼロから手で描く（手動デジタイズ）」も重視か。
7. **互換**：PES/DST 以外に必要な形式（JEF/EXP/VP3 等）はあるか。
8. **譲れない品質**：「これが守れないなら使えない」という実機での失敗例（糸切れ・密度過多・
   引き連れ等）があれば、判定基準として教えてほしい。
