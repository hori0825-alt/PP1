# 実機テスト手順書 (Brother PP1 / Artspira)

ソフト側の検証 (115テスト + PES/DST ラウンドトリップ) は自動化済みですが、
「実際に縫える」ことの最終確認は実機でしか行えません。特に
**糸切り回数が表示どおりか**を必ず確認してください。

## 準備するもの

- Brother PP1 本体・刺繍枠・台
- スマートフォン (Artspira アプリ)
- 刺繍用の布・下紙 (安定紙)・上糸 (赤/青/黄/緑があると全サンプル確認可)
- このリポジトリの `samples/` にある `.pes` ファイル

## 手順

### 1. サンプルを用意する

`samples/` には生成済みの `.pes` があります。再生成する場合:

```bash
npm run samples
```

各サンプルの内容と期待値は `samples/README.md`、個別の期待値/実測値は
`samples/<id>.json` に記載しています。

### 2. Artspira にインポートする

1. Artspira アプリを開く
2. PES ファイルのインポート機能で `samples/a-solid-circle.pes` を読み込む
3. AR プレビューで配置を確認する

### 3. PP1 へ転送して縫う

1. Artspira から Bluetooth で PP1 へ転送
2. 布と下紙をセットして縫製を開始
3. 下表の「確認ポイント」を観察する

## サンプルと確認ポイント

| サンプル | 確認ポイント | 期待 |
|----------|-------------|------|
| **a-solid-circle** | 円の塗りを縫う間、**糸切りが一度も起きない**こと。針が止まって糸を切る動作をしない | 糸切り 0 回 |
| **b-donut** | 中央の穴が糸で**埋まらない**こと。青を縫い終えてから黄に**1回だけ**色替え | 色替え 1 回 / 糸切り 0 回 |
| **c-scatter** | 同じ赤の花びら同士で**無駄な糸切りが起きない**こと。糸切りは離れた領域への移動時のみ | 色替え 2 回 / 糸切り 6 回以下 |

### 合格基準

- **a-solid-circle で糸切りが発生したら不合格** — 面縫いの連続性が壊れています。
  `src/stitch/tatami.ts` の Travel on Edge を確認してください。
- b-donut の穴が埋まる場合は領域抽出の穴処理 (`src/import/regions.ts`) の問題です。
- c-scatter で糸切りが期待を大きく超える場合は縫い順最適化
  (`src/plan/order.ts`, `src/stitch/digitize.ts`) を確認してください。

## トラブルシューティング

- **Artspira がインポートを拒否する**: PES のフープが 100mm に設定されているか確認
  (`src/export/pes.ts` のフープ ID = 0)。糸色が化ける場合は Brother パレットへの
  マッピング (`src/export/brotherPalette.ts`) を確認。
- **縫いズレ・布の引きつれ**: 下紙を追加し、`samples` を小さめサイズで再生成して
  密度を下げる。アプリ側の自動削減 (診断タブ) も利用できます。
- **針数が画面表示と実機で食い違う**: 本ツールの「針数」は通常ステッチのみを数え、
  ジャンプ・色替えは含みません。Artspira の表示はジャンプを含む場合があります。

## 結果の記録

各サンプルについて、実機での糸切り回数・色替え回数・所要時間を測り、
`samples/<id>.json` の `expect` と照合してください。差異があれば
GitHub Issue または `docs/STATUS.md` に記録します。
