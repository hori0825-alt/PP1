## 2. 現在の刺繍データ生成フロー

```
画像 → ①Oklab減色 (エッジ除外k-means + 階層統合 + 弱い島吸収)
     → ②色ごとの8連結コンポーネント分解
     → ③縫いモード判定 (幅p90 + コンパクトネス): タタミ / サテン / センターライン
     → ④細い線: スケルトン化 → グラフ → 行き=アンダーパス/帰り=本縫いの一筆書き
     → ⑤面: 走査線タタミ (蛇行連続・穴回避) + 輪郭ランニング
     → ⑥縫い順: 断片化の激しい色を先に / 線画系を最後に。
        色内は nearest-neighbor (run反転・閉ループ回転)
     → ⑦接続: 隠れ経路 (同色内 or 後で縫う色の上) はつなぎ縫い、
        直線がだめなら迂回BFS、それでも無理なら TRIM+JUMP
     → ⑧針数上限の自動密度調整 → PES/DST 出力
```

## 3. 糸切り問題の原因 (特定済み・対策済み)

| 原因 | 対策 (実装済みバージョン) |
| --- | --- |
| 全JUMPに糸切りフラグを付けていた | TRIM明示時のみ糸切り (v0.5) |
| run毎に分断・縫い順が面積順 | NN縫い順 + つなぎ縫い (v0.5) |
| 線がスキャン分割され大量の細切れrun | スケルトン一筆書き (v0.7) |
| 渡りが他色を横切り見える | 隠れ経路判定 (v0.8) |
| アンチエイリアス色の島が大量発生 | Oklab+遷移画素除外 (v0.8-0.9) |
| 後縫い色に覆われる渡りまで糸切り | 被覆ルール (v0.8) + 断片化順 (v0.10) |
| 先縫い色の島(穴)を直線で跨げない | 迂回BFSルーティング (v0.10) |

実測: 同一テストデザインで 157回 → 2回 (色替えのみ)。

## 4. PES/DST出力の現状

- PES v1 (CEmbOne/CSewSeg + PEC) / DST とも pyembroidery 読み戻しで
  ステッチ数・サイズ・色数の一致を検証済み
- PES糸色: Brother PEC 64色へ最近色マッピングで保持
- 既知の制約: PES v1 のため Artspira 上の表示色は PEC 64色に丸められる
  (v6 拡張で任意RGB保持は可能 — Phase 6 候補)

## 6. 針数計算の現状

- 総針数・色別割合・糸切り/ジャンプ/色替え回数・推定時間を表示
- 上限超過時は行間隔→サテン間隔→ステッチ長の順に自動緩和 (digitizeWithLimit)
- 上限は UI 設定 (既定9000 / PP1絶対上限としては12000を推奨値としてUIに明記予定)

## 7. 色数処理の現状

- Oklab知覚距離 + エッジ(遷移)画素のクラスタ推定除外 + 階層統合 (色数は上限)
- 微小クラスタ・弱い島の吸収 / クリックでの手動色修正 (v0.12)

## 8. 改修方針 (仕様 → 実装マッピング)

仕様の中核要件のうち **実装済み**:
糸切り最小化 / 面縫い連続性 / Branching相当(スケルトン一筆書き) /
Closest Join相当(NN+端点反転+閉ループ回転) / 渡り糸制御(隠れ経路+迂回) /
穴あき形状 / 色数削減 / 輪郭スムージング / 針数上限+自動削減 /
PES+DST / 糸切り・渡りの可視化 / 抜き・色修正のクリック編集

**未実装で優先度の高いもの** (次フェーズ):
1. 糸切り閾値の3段階UI (Always/Never/Auto Trim + Trim Distance) — 既存 reduceTrims/maxConnect の一般化
2. シーケンスビュー (色/オブジェクト単位の縫い順一覧・並べ替え)
3. ステッチプレイヤー (スライダーで針位置を再生)
4. 下縫い (センター/エッジ/ジグザグ) と Pull Compensation
5. 出力前診断パネル (短すぎ/長すぎステッチ・枠外・色保持チェックの一覧化)
6. SVG入力 / 文字刺繍 (フォント) / プロジェクトJSON保存
7. かんたん/プロ モードUI再構成
8. PhotoStitch / 3D / アップリケ / ライブラリ (基盤を壊さず追加)
